# Our Little Universe — Phase 0 UI 页面审查

审查日期：2026-11-16

## 1. 代码结构结论

- 前端没有路由库，也没有独立的页面目录。`App.tsx` 使用 `Page` 联合类型和条件渲染承载 18 个顶层页面。
- 独立 React 组件只有 `App` 与 `HomeGame`。其余详情、编辑、加载、错误等状态都内嵌在 `App.tsx`。
- 通用顶栏仍出现在除桌面与 HOME 游戏外的所有页面。旧底部四项导航已经从渲染结构移除。
- SETTINGS 入口首页已使用独立的 `atelier-page` 布局；其七个入口打开后仍回到旧 `feature-page` 模板。
- MEMORY、JOURNAL、CINEMA、CALENDAR、PROFILE、WORLD BOOK、THEMES、SERVICE、COMPANION、BACKUP、MIGRATION 仍主要复用 `feature-page`。
- JOURNAL、CINEMA、CALENDAR 共享同一组 `lifeTitle`、`lifeContent`、`lifeNotes` 状态与 `life-form` / `life-list` 布局。

## 3. 同页交互状态清单

这些状态真实存在，但目前不是独立路由：

- CHAT：空状态、有消息、加载更早、流式输入、停止生成、语音生成中/失败/可播放、文字转写展开、错误与重试。
- CALLS：空闲、拨号/通话中、监听中、播放中、通话结束后的记忆整理成功/失败。
- MEMORY：后端在线/预览、分类筛选、分页、内联编辑、证据展开、归档状态、整理最近聊天状态。
- PROFILE：加载、阅读、编辑、导入。
- MUSIC：未配置、加载、推荐、搜索、榜单、榜单详情、月报。
- COMPANION：加载、开关状态、勿扰时间、推送状态、通知健康、失败重试。
- BACKUP：空状态、校验中、校验成功预览、合并结果。
- MIGRATION：未导入、导入完成、提取准备/运行/暂停/需重试/完成、候选编辑、候选分页、冲突、完整性报告、错误。
- HOME：一楼/二楼/庭院、门户靠近、人物互动、宠物互动、播种/浇水/成熟/收获、提示气泡、横屏提示、自动存档。

## 4. 需求中尚未存在的页面或功能

以下内容不能仅通过重新排版“完成”，后续应先保留现有数据模型，再按真实能力逐步补齐：

- SETTINGS：独立语音选择/试听/音量配置；模型选择；备份历史；主题颜色、字体、背景编辑。
- MEMORY：独立新建记忆、信件类型、相册详情、照片详情、统一搜索。
- JOURNAL：编辑已有日记、照片插入、历史版本、日期索引、搜索。
- MUSIC：站内播放/暂停/切歌/音量/进度、站内收藏与播放列表持久化。当前真实能力是查询后跳转 QQ 音乐。
- CINEMA：海报字段、评分字段、观看状态字段、搜索与筛选。
- CALENDAR：真实日期、提醒、纪念日、倒数日和事件编辑。目前数据只有标题、正文、创建时间。
- CHAT：会话列表、图片消息、图片查看、长按菜单、回复与收藏状态。
- HOME：可打开背包、工具选择、家具编辑、游戏菜单与存档管理；当前工具栏多数按钮没有点击行为。

## 5. 共享样式审查

### 应继续共享

- 颜色、字体、字号比例、间距、线条、阴影、动效速度与 `prefers-reduced-motion`。
- 基础按钮、输入框、选择器、文件选择、焦点态、禁用态、加载/错误/成功反馈。
- 全局返回桌面能力、弹层层级、安全区与触摸目标规范。

### 需要拆分为应用布局

- `feature-page`：当前承担过多页面的外壳职责。
- `life-form` / `life-list`：日记、影院、日历不应继续共用相同内容结构。
- `soft-card`：只能保留为低层容器，不再作为所有反馈的视觉答案。
- 通用 `header`：保留功能语义，但需允许每个空间决定表现形式。

### 可保留但必须改造

- `memory-grid`、`memory-list`：保留数据操作，重组为空间化收藏、详情和编辑视图。
- `worldbook-form`、`worldbook-list`：保留 CRUD，拆为目录、阅读和编辑模式。
- `theme-options`：保留主题应用逻辑，升级为实验室预览。
- `service-form`：保留地址和口令存储逻辑，升级连接状态和分区。
- `companion-settings`：保留开关和时间逻辑，替换传统设置行。
- `candidate-review`：保留迁移审查能力，升级为专用审查桌。

## 6. 导航审查

- `history` 数组提供应用内返回；直接以 URL 打开子页时返回桌面。
- 旧底部四项导航已经移除。
- 除桌面和 HOME 外仍使用同一个头像顶栏，后续应替换为各空间的轻量返回入口。
- SETTINGS 的“模型与接口”和“语音与通话”目前都导航到 `service`，语音实验室没有独立 Page。
- MEMORY 与 GALLERY 是两个顶层入口，但产品概念上需要在记忆收藏室中建立明确关系。

## 7. Phase 0 数量与后续基线

- 已审查：18 个顶层 Page、1 个锁屏、1 个全屏来电层、约 37 类同页交互状态。
- 现有独立 React 页面组件：2 个（`App`、`HomeGame`）。
- 已完成新版视觉：首页级仅 SETTINGS 入口工作台；其余子页未完成。
- Phase 1 应先建立低层设计原语与状态组件，不改业务 API。
- Phase 2 应拆分并完成 SETTINGS 的 service、voice、companion、migration、backup、worldbook、themes 全部内部状态；其中尚无真实业务能力的项必须标注，不能伪造成功。

## 8. 本阶段功能保护结果

Phase 0 只做审查文档，没有修改页面逻辑、数据结构、API、部署流程或游戏逻辑。
