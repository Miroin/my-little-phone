# 小手叽 v2 完成度

更新时间：2026-11-09

## 已完成并落到代码

- React + TypeScript + Vite 前端、FastAPI 后端、SQLite 持久层；旧版 `index.html` 保留，v2 独立运行。
- DeepSeek 与 MiniMax 密钥只由后端环境变量读取，前端只保存后端 HTTPS 地址。
- 可选的服务访问口令保护全部聊天、记忆、相册和付费模型接口；调度器使用独立令牌。
- 流式文字聊天、停止、幂等重试、最近上下文、人格/关系/当前场景分层提示词。
- 七层长期记忆、原文证据、混合检索、使用记录、编辑、加强、归档恢复、永久删除与反馈权重；记忆页可直接回查原文证据。
- ChatGPT `conversations.json` 原文归档、本地初筛、DeepSeek 分段精提取、分页预览、编辑、去重、冲突保护、断点恢复和完整性报告；长会话按 20 条消息持久分段，失败只重试对应段，不再遗漏第 80 条之后的内容。
- 完整备份与安全合并恢复；覆盖聊天、通话、记忆、原文、迁移任务、人物档案、陪伴设置、共同生活、相册和已生成语音文件，不包含 API Key 或服务访问口令。
- MiniMax Speech 2.8 真实 MP3 语音消息、语音条、可展开文字；模型可自主选择是否发语音。
- 主动语音会在推送派发前由后端预生成，打开聊天时直接显示语音条，不再暴露 `[voice]` 标记。
- 通话开始/接听/拒绝/挂断、准确计时、刷新续接、双方逐轮原文、聊天内通话卡片；浏览器语音识别 → DeepSeek → MiniMax 播放形成连续语音回合，播放中可打断接话。
- 主动陪伴决策、自由触发、勿扰时段、未回复防轰炸、主动消息、主动来电、前台全屏来电弹窗；主动内容与通话开场共用人物档案、关系记忆和互动反馈。
- “像/不像沈砚”会按实际场景参与后续聊天与通话判断，单次负评只作修正信号，不会被粗暴写成全局人格命令。
- MiniMax 语音生成使用服务端原子占位，避免刷新或并发请求重复扣费；失败后必须由用户手动重试。
- Web Push 订阅、通知队列、后端调度保护和 iPhone 主屏幕安装说明。
- Web Push 密钥首次启动自动生成并保存到持久磁盘，无需用户手工制作密钥对。
- 沈砚/陈钰同页切换的六类人物档案，支持编辑和 JSON 导入；文字聊天与电话都会读取档案。
- 固定 A-J 互动回归集和可选真实模型评分脚本。
- PWA manifest、Service Worker、离线外壳；Capacitor Android/iOS 原生工程、麦克风与语音权限基础。
- Docker 后端、Render 持久磁盘蓝图、环境变量模板和部署说明。
- GitHub Actions 主动陪伴调度，每五分钟触发决策与推送派发，不需要额外定时任务服务。
- 共同日程、生活记录、一起听歌和回忆相册；支持添加、查看、删除并进入完整备份。
- 长期记忆支持完整分批读取、分类筛选和分页，不再只显示前几十条。
- 聊天记录从最新一页开始读取，可按需持续加载更早消息，不受固定 500 条展示上限影响。
- 通话结束后自动生成带原文证据的待确认记忆候选，只有用户确认后才参与后续对话。

## 需要外部账号或真机才能完成的发布步骤

- 部署持续运行的后端并填入 DeepSeek、MiniMax、VAPID 密钥。
- 在 GitHub Actions 中填写后端地址和调度令牌，让仓库自带的定时工作流开始运行。
- 将主动陪伴工作流随验收版本合并到仓库默认分支；GitHub 不会从仅存在于功能分支的 workflow 执行定时任务。
- iOS 原生包签名、APNs、CallKit 和真机审核需要 Apple Developer Team、证书与 Mac/Xcode。
- Android 系统级来电界面和商店签名需要 Android 构建/签名环境。
- iPhone Safari 后台限制仍然存在：关闭网页后的主动联系依赖已安装 PWA、用户通知授权和持续运行的后端。

## 当前技术边界

- 网页通话已是连续语音回合，可说话、转写、生成并自动播放；它还不是支持任意插话打断的全双工音频流。
- 系统锁屏级来电必须使用原生 CallKit/Android Telecom，PWA 只能使用推送通知和打开后的全屏来电页。
- GitHub Pages 只托管前端；后端部署之前，线上页仍处于预览模式，可在“设置 → 模型与接口”填写部署后的服务地址。
